## Design (approved in Part B)

* Python Streamlit, not FastAPI: an internal, widget-driven analyst tool with no REST consumers.
* Shared code, not a rewrite: `scripts/sync_app_modules.py` copies `fraud_triage_agent.py` and `lakebase_cases.py` from the repo root into `app/` and checks sha256. Current hashes: `fraud_triage_agent.py` 7ef49d2db69b8aabf082249b1c60065c0afc58dc9c3a41c66b15a174b2f74293, `lakebase_cases.py` 84364c4395330de0edf265459b6f18a697b5ef067c2396933cacec391e7aca40 (identical at root, in `app/`, and in the deployed snapshot).
* The agent runs in-process in the app and calls the FM endpoint. No Model Serving endpoint: MLflow's `DatabricksLakebase` resource only accepts a provisioned `database_instance_name`, and `fe-bar-fraud-analytics` is an Autoscaling project.
* Thresholds are passed as env vars read from MLflow run d89beaca8f81447780da60ed2ea7c811 at build time: block 0.9502674433961342, review 0.8714158290727556.
* Pages: Triage queue (top 50 block/review from `fraud_gov.txn_risk_current` as `fraud_triage_agent`), Transaction detail (Explain, Open case through the agent's `create_fraud_case`), Ask Genie (space 01f1d7b464d510b9aa6cde48300787ca: answer, SQL, result table), dashboard link (01f1ce7f835a1e81b05ebb664bf0994c).
* Logging: one JSON line per Explain / Open case / Genie question to stdout (timestamp, page, txn_id, case_id or conversation ID, latency_ms, ok).
